# 第一期实施计划：电商多 Agent 框架小闭环

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 搭建电商超级个体多 Agent 运营助手第一期小闭环，让 5 个 Python Agent 全部参与一次完整业务流，并通过 Java 电商业务系统保存商品、库存、订单、运营建议和 Agent 执行记录。

**Architecture:** 第一阶段采用“大框架、小闭环”。Python 侧先实现 5 Agent 固定顺序编排和结构化输出，再服务化为 FastAPI；Java 侧实现最小电商业务系统和 PostgreSQL 落库；最后完成 Java 调 Python、Python 调 Java Tool API 的同步 HTTP 闭环。

**Tech Stack:** Java 21、Spring Boot 3.x、Spring Data JPA、PostgreSQL、Flyway、Maven、Python 3.11+、FastAPI、Pydantic v2、LangGraph、LangChain 基础包、HTTPX、pytest、loguru、uv、Docker Compose。

---

## 1. 已确认范围

第一期项目名称：

- 电商超级个体多 Agent 运营助手。

第一期策略：

- 大框架。
- 小闭环。
- 5 个 Agent 全部存在。
- 每个 Agent 功能先轻量实现。
- 先用规则、模板或轻量 LLM 调用，不强制接入真实大模型。

第一期业务闭环：

```text
商品录入
  -> Agent 运营分析
  -> 库存补货建议
  -> 订单出货建议
  -> 结果落库
```

第一期 5 个 Agent：

- Supervisor Agent。
- Product Planning Agent。
- Image Creative Agent。
- Inventory & Purchase Agent。
- Order Fulfillment Agent。

第一期数据表：

- `products`。
- `inventories`。
- `orders`。
- `operation_plans`。
- `agent_runs`。

第一期 API 分组：

- 用户或前端调用 Java 的业务 API。
- Java 调 Python 的 Agent API。
- Python 调 Java 的 Tool API。

## 2. 不做事项

第一期不做：

- 真实电商平台 API。
- 真实支付、退款、售后。
- 真实物流系统。
- 真实图片生成服务。
- 多店铺、多平台、多租户。
- 复杂权限系统。
- 完整前端管理台。
- 消息队列。
- Kubernetes。
- 复杂库存预测模型。
- 复杂搜索、分页、删除 API。

## 3. 推荐开发顺序

第一期按下面顺序开发：

1. Python 多 Agent 原型。
2. Python FastAPI 服务化。
3. Java Spring Boot 最小业务系统。
4. PostgreSQL 与 Flyway 表结构。
5. Java 业务 API。
6. Java 调 Python Agent API。
7. Python 调 Java Tool API。
8. 端到端小闭环验证。
9. README 和演示数据。

这样排序的原因：

- 先把多 Agent 框架跑通，避免一开始陷入 Java CRUD 细节。
- Python Schema 先稳定，Java 调用协议更容易确定。
- Java 表结构和 API 按已确认 Agent 输出落库，不会发散。
