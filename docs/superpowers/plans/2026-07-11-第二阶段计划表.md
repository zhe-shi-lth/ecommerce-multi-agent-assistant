# 第二阶段计划表（阶段 5：Agent 能力增强 + 阶段 6：作品化）

> 本表为第二阶段权威执行基准，后续严格按表推进。每完成一步更新「状态」与记忆。
> 总体精神：延续第一期「大框架、小闭环」——保持落库契约稳定，外部 API 不盲目接，前端保持轻薄。

## 已锁定决策
- LLM：本地 Ollama（OpenAI 兼容），结构化输出复用现有 Pydantic Schema，Java 落库契约不变。
- 前端：独立 **React + Vite + TypeScript** SPA（`frontend/`），只调 **Java REST**；开发期 Vite proxy 代理 `/api`，不改 Java CORS。
- 外部 API（图片/物流）策略：**到达对应步骤时再定**（先 LLM+规则模拟，或接真实服务），此决策影响步骤 2/4 范围与是否新增表。
- 降级：LLM / 外部调用失败一律降级到规则实现并继续，不中断主链路。

## 阶段 8：用户流程重构（按真实运营节奏，两条线）

> 关键重构：从「一次性并行出四块」改为「上架流水线（顺序门控）+ 日常监控（事件触发）」两条线。
> - **线一 上架流水线**（用户主动）：输入想法 → 商品文案 Agent → 人审 → 图片创意 Agent → 人审 → 定稿。
> - **线二 日常监控**（系统自动）：库存 Agent（按真实日销触发补货提醒+人审）；履约 Agent（每笔订单发货前风控+人审）。
> - Supervisor 改为编排两条线 + 维护每步审批状态机。
