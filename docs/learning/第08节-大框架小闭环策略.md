# 第 08 节：大框架、小闭环策略

## 1. 学习目标

本节目标是理解本项目第一期为什么采用：

```text
大框架，小闭环
```

这既不是大而全平台，也不是小脚本 Demo，而是适合学习和就业展示的中间路线。

## 2. 什么是大框架

大框架不是一开始做很多复杂功能，而是第一期就让核心架构形态出现。

第一期要有：

- Python Agent 服务。
- Java 业务服务。
- PostgreSQL 数据库。
- 5 个 Agent。
- Supervisor 编排。
- 结构化输出。
- Agent 执行记录。
- Java 调 Python。
- Python 调 Java Tool API。
- 端到端 trace。

关键角色都出现，关键链路都打通，关键边界都建立。

## 3. 什么是小闭环

小闭环指业务范围克制。

第一期只跑通：

```text
商品录入
  -> Agent 运营分析
  -> 库存补货建议
  -> 订单出货建议
  -> 结果落库
```

第一期不做完整电商系统，不做支付、退款、真实发货、物流、售后、店铺和多平台。

闭环小，但完整：

- 有输入。
- 有 Agent 分析。
- 有结构化输出。
- 有落库。
- 有查询。
- 有执行记录。

## 4. 为什么不能一开始做大而全

一开始做大而全会导致：

- 学习压力过大。
- 项目周期失控。
- Agent 主线被 Java CRUD 淹没。
- Python 多 Agent 做得很薄。
- 很难形成阶段性成果。

本项目要的是：

```text
项目小，但架构清楚
功能少，但链路完整
Agent 不深，但协作明显
```

## 5. 为什么不能只做小 Demo

如果只写一个 Python 脚本：

```text
输入商品
输出标题、图片提示词、补货建议
```

它太轻了。

问题是：

- 没有 Java 企业系统。
- 没有数据库。
- 没有 API。
- 没有执行记录。
- 没有 Tool Calling。
- 没有真实业务边界。

所以我们要避免：

```text
大而全平台  -> 太重
小脚本 Demo -> 太轻
```

选择：

```text
大框架 + 小闭环
```

## 6. 第一阶段完整性体现

架构完整：

```text
Java 服务
Python 服务
PostgreSQL
Docker Compose
HTTP 通信
```

Agent 完整：

```text
Supervisor
Product Planning
Image Creative
Inventory & Purchase
Order Fulfillment
```

数据完整：

```text
products
inventories
orders
operation_plans
agent_runs
```

API 完整：

```text
用户调 Java
Java 调 Python
Python 调 Java Tool API
```

链路完整：

```text
创建数据
触发分析
多 Agent 执行
结果返回
结果落库
查询结果
```

## 7. 第一阶段的小体现在哪里

业务小：

- 只做商品、库存、订单。

能力小：

- Agent 先用规则和模板。

动作小：

- 只保存建议，不做真实支付、退款、发货。

界面小：

- 先用 API，不急着做完整前端。

数据小：

- 用示例数据或模拟订单。

## 8. 后续增强路径

框架搭起来后，可以逐个增强：

- Product Planning Agent：LLM 文案、SEO、A/B 标题。
- Image Creative Agent：图片生成、图片审核、主图评分。
- Inventory & Purchase Agent：销量预测、安全库存模型、供应商比较。
- Order Fulfillment Agent：物流选择、异常订单、售后联动。
- Supervisor Agent：动态路由、失败重试、人工确认策略。

## 9. 面试表达

可以这样讲：

> 项目第一阶段采用“大框架、小闭环”策略，先搭建 Python 多 Agent 协同层与 Java 电商业务系统的端到端闭环。系统包含 5 个 Agent、统一 Supervisor 编排、结构化输出、Tool API、trace_id 和 agent_runs 执行记录。第一期先使用规则和模板实现最小 Agent 能力，确保架构稳定和流程可追踪，后续逐步增强 LLM 文案生成、图片创意、库存预测和订单履约能力。

## 10. 小结

“大框架、小闭环”就是第一期让系统形态完整，但业务范围克制。

先把 Java + Python + 5 Agent + 数据库 + API + trace 的主链路跑通，再逐步增强每个 Agent 的智能能力。
