# 第 15 节：失败处理与降级策略

## 1. 学习目标

本节目标是理解企业级 Agent 系统不能只设计成功路径，还必须设计失败处理和降级策略。

本项目链路较长：

```text
Java
  -> Python Supervisor
  -> 4 个子 Agent
  -> Tool API
  -> Java 落库
  -> 查询结果
```

任何一步都可能失败。

## 2. 常见失败类型

### 2.1 输入数据失败

例如：

- 商品不存在。
- 库存不存在。
- 订单不存在。
- 商品价格为空。
- 销售价低于成本价。
- 订单数量小于等于 0。

这类失败一般应由 Java 先校验。

### 2.2 Agent 执行失败

例如：

- Product Planning Agent 生成失败。
- Image Creative Agent 生成提示词失败。
- Inventory Agent 计算异常。
- Order Fulfillment Agent 判断异常。

这类失败要记录到 `agent_runs`。

### 2.3 结构化输出失败

后续接入 LLM 后可能出现：

- 缺字段。
- 字段类型不对。
- 枚举值不合法。
- 返回自然语言而不是 JSON。

处理方式：

```text
Pydantic 校验
校验失败 -> 重试一次
仍然失败 -> 降级模板输出
记录错误
```

### 2.4 Java 调 Python 失败

例如：

- Python 服务没启动。
- Python 接口超时。
- Python 返回 500。
- Python 返回结构不符合 Java DTO。

Java 应设置超时、捕获异常，并返回明确错误。

### 2.5 Python 调 Java Tool API 失败

例如：

- 查询商品失败。
- 查询库存失败。
- 保存 `agent_runs` 失败。
- 保存 `operation_plans` 失败。

Python 侧不能悄悄吞掉错误，应把错误传给 Supervisor，并写入最终结果。

## 3. 降级策略是什么

降级策略是：

> 当智能能力或某个服务失败时，系统用一个更简单但可控的方式继续工作。

例如 Product Planning Agent 后续接入 LLM，如果 LLM 失败，可以用模板生成标题。

## 4. 不同 Agent 的降级策略

### 4.1 Product Planning Agent

LLM 失败时降级为模板标题和卖点。

### 4.2 Image Creative Agent

图片创意失败时返回通用模板提示词。

### 4.3 Inventory & Purchase Agent

规则判断优先。LLM 解释失败时，规则结果仍然可用，`reason` 可用模板生成。

### 4.4 Order Fulfillment Agent

涉及业务风险，必须规则优先。

如果判断失败，应保守处理：

```text
can_ship = false
manual_review_required = true
next_order_status = NEEDS_REVIEW
```

## 5. 失败时要保守

企业 Agent 的重要原则：

```text
不确定时，不自动执行高风险动作
```

例如：

- 不确定订单是否已付款 -> 不出货。
- 不确定库存是否足够 -> 不出货。
- 不确定图片是否合规 -> 人工确认。
- 不确定补货数量是否合理 -> 人工确认。

低风险可以降级继续，高风险必须转人工。

## 6. Supervisor 如何处理子 Agent 失败

建议策略：

```text
Product Planning Agent 失败 -> 记录错误，模板降级，PARTIAL_FAILED
Image Creative Agent 失败 -> 记录错误，模板降级，PARTIAL_FAILED
Inventory Agent 失败 -> 记录错误，manual_review_required = true
Order Fulfillment Agent 失败 -> 记录错误，manual_review_required = true
Supervisor 自身失败 -> FAILED
```

库存和订单更靠近业务执行风险，因此失败更严重。

## 7. operation_plans 状态

`SUCCESS`：

```text
5 个 Agent 都成功，最终建议完整，没有严重错误。
```

`PARTIAL_FAILED`：

```text
某个非关键 Agent 失败，或某个 Agent 使用降级结果，但系统仍能给出可查看建议。
```

`FAILED`：

```text
核心输入缺失，Supervisor 失败，或无法生成有效结果。
```

## 8. agent_runs 状态

第一期状态：

```text
SUCCESS
FAILED
SKIPPED
```

如果使用降级，第一期可以在 `output_json` 中标记：

```text
fallback_used = true
```

并在 `error_message` 中记录原始错误。

## 9. 超时与重试

所有服务调用都应有超时。

适合重试：

- 网络抖动。
- 临时 502。
- LLM 输出格式错误。
- 短暂超时。

不适合盲目重试：

- 商品不存在。
- 订单不存在。
- 参数校验失败。
- 库存数据不合法。

## 10. 面试表达

可以这样讲：

> 我在设计 Agent 系统时没有只考虑成功路径，而是把失败分成输入数据失败、Agent 执行失败、结构化输出失败、Java 调 Python 失败、Python 调 Java Tool API 失败几类。第一期通过 trace_id、agent_runs、operation_plans.status 和 errors 记录失败过程。对于内容生成类 Agent，可以降级到模板输出；对于库存和订单履约这类高风险判断，失败时会保守地设置 manual_review_required，进入人工确认。

## 11. 小结

企业级 Agent 系统必须设计失败处理和降级策略。

内容生成失败可以模板降级，库存和订单这类高风险判断失败要保守转人工。所有失败都要能通过 `trace_id`、`agent_runs` 和 `operation_plans.status` 追踪。
